## 三、初赛提交的四项（均为必选）

> 原文见赛制说明 P25。

### 1. 方案书（必选）

**PDF 文档，字数不少于 5000 字**，需包含以下 **8 个部分**：

1. 选题背景与场景需求分析
2. 平台总体架构设计与技术选型说明
3. Agent 角色定义、工作流设计与编排逻辑详解
4. 调度算法与自我循环机制说明
5. 结果验证策略与反馈优化逻辑
6. 核心代码模块说明与系统截图
7. 测试用例、运行效果与性能评估
8. **人工智能使用说明**（各环节 LLM、RAG、MCP 等的实际作用、贡献与局限）

### 2. 方案讲解 PPT（必选）

**正文 10~15 页**，清晰展示架构、流程、创新点与演示效果。

官方模板规格（`2026未来杯PPT模版.pptx`，16:9）：

| 页 | 内容 | 规格 |
| --- | --- | --- |
| P1 | 题目 / 团队名称 / 演讲人 / 指导教师 / 学校 | 思源黑体 Bold 32 号；信息行 20 号；**题目不加书名号** |
| P2 | 目录（一级 20 号 Bold、二级 18 号 Normal） | — |
| P3–P4 | 内容页（小标题 24 号 Bold） | — |
| P5 | 大会提示：**不得出现国家领导人照片、国家地图** | 硬性合规 |
| P6 | 谢谢观看 / Thanks | — |

### 3. 演示视频（必选）

**3~5 分钟**，须完整展示：平台界面、Agent 编排过程、任务调度执行、结果验证与反馈循环的关键操作。

### 4. 可运行代码或部署链接（必选）

提供 **Demo 源码仓库地址（GitHub / Gitee 等）**或**在线演示环境**，
**确保评审专家可复现演示功能**。

## 四、赛题一的功能要求（赛制说明 P21–P22）

必须覆盖**五个核心模块**：Agent 定义与配置、工作流编排、任务调度与执行、结果验证与监控、反馈循环与优化。

另需满足：

- 必须提供**可运行的系统原型**，不接受纯概念设计 / 纯 PPT / 无代码的论文综述；
- 必须体现**多 Agent 协作**，单 Agent 简单调用不符合要求；
- 必须包含至少一个**自我循环或迭代优化机制**。

题目概述里列出的六项能力（知识库、Agent 团队、工作流编排、智能调度、工具集成、执行监控与验证、反馈与自我优化）与本项目六模块一一对应。

### 关于"不写校名导师"这条旧规则

我们早期自拟的 `tests/test_project_doc_skeleton.py::test_no_personal_identity_leak`
禁止出现校名/导师/学号。**官方模板 P1 明确要求填"指导教师""学校"**。

处理原则：

- **方案书正文、代码、仓库**里不写个人信息（防泄露，这条保留）；
- **PPT 封面**按官方模板要求填写学校与指导教师（这是赛事要求，不是泄露）；
- 测试相应放宽：允许出现在 PPT 说明中，禁止出现在方案书正文与代码里。
