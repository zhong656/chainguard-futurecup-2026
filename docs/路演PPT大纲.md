## P3 · 为什么做「可核验」

**痛点**：多智能体系统最容易出的问题不是"写不出来"，是**写出来的东西无法核实**——
数字哪来的？引用了哪段原文？失败过几次？改过几轮？

**我们的回答**：把"可核验"做成交付物的结构，而不是事后补一段说明。
**证据**：`outputs/_vertical/` 9 件交付物（P11 展开）

## P7 · 动态调度：失败是被记录的，不是被掩盖的

**要点**：并发信号量、单节点超时、指数退避重试、失败降级、预算护栏。
**演示**：`python -m src.run --inject-fault timeout --node retrieve`
**数据**：trace 里 `fail`×3 / `retry`×2 / `degrade`×7，随后**安全中止并保留 trace**。
**口径**：降级不是"继续交付"，是**宁可不出包，也不出带病的包**。
**证据**：`trace.jsonl`；`docs/黄金用例.md` G4

## P8 · Self-Loop：定位到段落，只重跑相关节点

**要点**：评分未达 0.85 → 生成落到段落的修订指令 → 只回退 `write→verify`，其他分支保留。
**数据**（最有说服力的一页）：

| 轮次 | 分数 | 结论 |
| --- | --- | --- |
| R0 | **0.95** | **fail**（1 条 blocker） |
| R1 | 1.0 | pass |

**讲法**：0.95 已经高于阈值 0.85 却判 fail —— 一票否决真的在起作用。
**证据**：`rounds.json`；`docs/黄金用例.md` G2

## P9 · 验证体系：两层，第三层如实说没做

| 层 | 状态 | 说明 |
| --- | --- | --- |
| L1 确定性规则 | ✅ | 引用/数值/章节/Schema，5 条规则 |
| L2 独立评审 | ✅ | 温度与撰写者不同（0.0 vs 0.3），相同则拒绝启动 |
| L3 双路比对 | ✅ **已实现** | BM25/向量各自复核；只观测、不加权、不否决 |

**讲法**：能说清边界比宣称"全都做了"更经得起追问。
**证据**：`configs/verifier.yaml` + `tests/test_layers.py`（7 条）

## P10 · 可核验交付：9 件文件，全部进 manifest

```
solution.md / evidence_chain.json / evidence_refs.json / scorecard.json
rounds.json / trace.jsonl / charts/*.svg / delivery_artifact.json
```

**关键一件**：`evidence_refs.json` 给出每条引用的 **文件 / 页码 / 字符区间 / 原文 / 哈希**——
可以回到原文逐字核对。

> 口径：**页码仅 PDF/DOCX 等分页格式才有值**。当前 17 份语料是 Markdown，`page` 全为 `null`，
> 靠 `file_path + char_range + hash` 回原文；PDF 页码贯通**尚未用真实文件验证**，不要宣称已验证。

**讲法**：别人给结论，我们给"可回到原文的证据"。
**证据**：`delivery_artifact.json` 的 `manifest.files`（含逐个 sha256）
