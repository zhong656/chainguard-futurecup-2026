## 第 1 章 · 现状痛点与机会

**要点**（3–5 条）

1. 中小企业做质检改造，缺的不是"能不能拍"，而是**拍完能不能说清楚结论怎么来的**；
2. 大模型能写方案，但写出来的数字、引用、结论**没有出处**，评审/客户不敢用；
3. 多智能体系统普遍"能演示、不能交付"——失败过程被掩盖，交付物只有结论；
4. 机会：把"可核验"做成交付物的**结构**（证据链 + 清单 + 哈希），而不是事后补说明。

### §3.2 Agent 团队
- 六类角色全部 YAML；工具白名单、只读约束、模型档位在配置里；
- 改 YAML 不重启即生效（内容指纹热加载）。
- 证据：`agents/*.yaml`；`tests/test_agent_registry.py`

### §3.3 工作流编排
- DAG 编译 11 个节点；条件分支、并行 fanout、循环边、定向回退；
- 节点集合被契约约束（`target_node` 必须落在 verify 的合法前驱）。
- 证据：`workflows/industry_solution.yaml`；`src/dag_compiler.py`

### §3.4 动态调度
- 并发信号量、单节点超时、指数退避重试、失败降级、Token 预算；
- 故障注入可复现：`fail`×3 / `retry`×2 / `degrade`×7。
- 证据：`trace.jsonl`；`docs/黄金用例.md` G4

### §3.5 Self-Loop
- 未达 0.85 → 生成**落到段落**的修订指令 → 只回退 `write→verify`；
- 实测：R0 **0.95 fail**（1 条 blocker）→ R1 1.0 pass。
- 证据：`rounds.json`；`docs/黄金用例.md` G2

### §3.6 结果验证与反馈
- L1 五条规则；L2 独立评审（温度 0.0 vs 0.3，相同则拒绝启动）；一票否决；
- 失败样本入库，支持按规则统计与前后对比。
- 证据：`configs/verifier.yaml`；`tests/test_layers.py`；`src/feedback.py`

## 第 4 章 · 商业模式与落地路径

**要点**

1. **客户**：年产值 1–10 亿、有质检工位但不具备 AI 团队的中小制造企业；
2. **交付形态**：不是卖软件许可，是卖"可核验的改造方案"——方案 + 证据链 + 可复现验证；
3. **收费结构**（示例，需按实际调研修正）：方案诊断费 + 按工位实施费 + 年度验证服务；
4. **为什么客户会买"可核验"**：他们要向老板/银行/客户证明钱花得值，**证据链就是那份证明**；
5. 冷启动路径：先在 1–2 个工位做样板，用 `evidence_refs.json` 做验收依据。
