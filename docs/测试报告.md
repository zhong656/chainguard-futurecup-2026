## 三、Self-Loop 收敛

一次纵切产出 9 件文件（含 2 张 SVG）：

```
solution.md  evidence_chain.json  evidence_refs.json  scorecard.json
rounds.json  trace.jsonl  charts/scorecard.svg  charts/convergence.svg
delivery_artifact.json
```

`rounds.json` 记录每轮评分：

| 轮次 | 分数 | 结论 | 问题数 |
| --- | --- | --- | --- |
| R0 | 0.95 | **fail** | 1（`CITATION_MISSING`，blocker） |
| R1 | 1.0 | pass | 0 |

**这组数据最有价值的地方**：R0 的加权分 **0.95 高于阈值 0.85**，却因一条 blocker 判了 fail——
说明一票否决真的在起作用，不是摆设。**答辩时举这个例子比解释规则表更有说服力。**

复现：`python -m src.run` → 看 `outputs/_vertical/rounds.json`。

## 四、故障注入与降级

```bash
python -m src.run --inject-fault timeout --node retrieve
```

trace 事件统计：`start`×4、`fail`×3、`retry`×2、`degrade`×7、`end`×1。

三类关键事件**同时出现**，满足考察点 4 的"失败重试与降级"证据要求。

**降级后的行为是安全中止**，不是继续交付：

```
[FAIL] 纵切未完成：调度降级后没有评分结果，已保留 trace.jsonl
```

这是有意设计：**宁可不出包，也不出一个验证不过的包**。答辩口径必须这么说，
不要说成"降级后仍能继续交付"——现场演示会当场打脸。

## 七、已知限制（写材料时不要越过）

1. **语料是 17 份转述卡，不是真实行业资料**。检索评测证明"链路能查准"，**不代表真实语料下的检索质量**；
2. **改述查询 hit@1 仅 40%**，这是当前检索策略的真实短板，不要用总体 100% 掩盖；
3. **PDF/DOCX 的页码提取没有真实样本验证**：代码路径已通（`Chunk.page → source_ref.page` 有测试），但本机没装 `pymupdf`/`python-docx`，也没有真实 PDF 语料；
4. **L3 只观测**：一致率写进 `cross_check` 维度，但不进权重、不触发一票否决——它是提示人工复核的信号，不是总分的一部分；
5. **Mock 模式下的 L2 是启发式判定**（bigram 重合、段落矛盾检测），接真实模型后走同一接口——不要说成"大模型评审已经跑通"。
